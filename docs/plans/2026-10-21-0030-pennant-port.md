## Lifetime and coroutine state

Worker-lifetime (unchanged services): `FeatureManager` (stores, custom creators, default scope resolver, morph-map flag, partition resolver), `Decorator` (definitions `nameMap`, per-feature metadata), driver definitions (`featureStateResolvers`). Feature classes resolve through `make()` (auto-singleton, like policies and listeners); docs tell users to keep resolver classes stateless.

Mutator docblocks:

- `Boot or tests only.`: `define`, `discover`, `forgetDriver`, `forgetDrivers`.
- `Tests only.`: `setContainer` (kept, matches `Support\Manager`).
- Runtime-safe: `flushCache` (current coroutine only); internal dynamic class registration in `ensureDynamicFeatureIsDefined` (idempotent, bounded by feature classes; `DynamicallyRegisteringFeatureClass` fires once per worker per class).

`EnsureFeaturesAreActive` gets `flushState()`. Add `flushPennantState()` to the optional-package section of `AfterEachTestSubscriber` (alphabetical, between Passport and Permission): `callIfExists(EnsureFeaturesAreActive::class, 'flushState')` and `callIfExists(Decorator::class, 'flushMacros')` (Macroable keeps macros statically; `FeatureManagerTest::test_it_can_apply_macros`). ### `PennantState` (`src/PennantState.php`, `CONTEXT_KEY = '__pennant.state'`, implements `ReplicableContext`)

```php
/** @var array<string, array<string, array<string, array<string, array<string, mixed>>>>> [connection][store][partition][feature][scope] */
public array $values = [];       // Decorator memo, including before() results; '' connection for non-database drivers
/** @var array<string, array<string, array<string, array<string, mixed>>>> [store][partition][feature][scope] */
public array $arrayValues = [];  // ArrayDriver storage (per execution, like Laravel's per-request array driver)
/** @var array<int, array<string, true>> spl_object_id(DatabaseTransactionRecord) => set of memo connections */
public array $transactions = [];

public static function current(): static; // CoroutineContext::get(), set a new state on miss (one lookup on hits; getOrSet() would build a state per call)
public function replicate(): static;     // copy $values except connections present in $this->transactions, copy $arrayValues, empty $transactions
```

- Presence uses `array_key_exists` (stored `null`/`false` are hits).
- `replicate()` uses only the source object's own `$transactions`; it never reads ambient context (`CoroutineContext::copyFrom()` runs it in the destination coroutine).
- Transaction tracking (Decorator, for drivers implementing `UsesDatabaseConnection`): on any memo write for that connection (driver result, first resolution, mutation, or `before()` result, which may read uncommitted rows), if `DatabaseManager::hasApplicableTransaction($connection)` (held-state check by requested name, no pool borrow), take the record the manager would use: `db.transactions` → `callbackApplicableTransactions()` filtered by `->connection === ConnectionName::parse($connection)->base` (transaction records use the base name), `last()`. Add `$connection` to `$state->transactions[spl_object_id($record)]`; when the id is new, register on the record directly: `addCallback` → remove the id; `addCallbackForRollback` → unset `$state->values[...]` for every connection in the id's set, then remove the id. One record can cover several memo connections (in-memory SQLite shares one owner across base and `::write` aliases). Closures capture `$state` and the scalar id, not the record. Savepoints work: a released savepoint's record keeps its callbacks until the outermost commit, and rolling back an outer level runs its committed children's rollback callbacks. Under `RefreshDatabase` the testing manager excludes the wrapping transaction, so top-level test code registers nothing.
- `flushCache()` clears `$values` and `$arrayValues` buckets for the store, never `$transactions`. `forgetDriver()` / `forgetDrivers()` call it on each resolved store they discard, so a rebuilt store can't inherit the old one's memo or array values (current coroutine; these methods are boot/test-only).
- No Octane/`JobProcessed` listeners: requests, daemon jobs (`Worker` child coroutines) and lifecycle callbacks (`Waiter::wait()` children) each own their state; sync and deferred jobs share the caller's memo.
- Per-store memo semantics stay upstream's: a write through store A does not refresh store B's memo in the same request.
- Mutations (`set`, `setAll`, `delete`, `setForAllScopes`, `purge`) remove the affected memo entries of the current store before calling the driver and write new values only after it returns, so a post-commit cache failure that the app catches can't leave the old value in the local memo. A failed shared-cache rotation keeps the TTL-bound limitation described under Shared cache.

### Hot path

A memo-hit `Feature::active('x')` currently allocates ~25 Collections, scans the memo linearly three times, rebuilds `array_keys()` of every definition twice and always dispatches `FeatureRetrieved`. Target: one `PennantState` lookup and array reads.

- `PendingScopedFeatureInteraction` and `Decorator` work on plain arrays. Normalize features and scopes once per operation (list-form entries share one default-scope resolution); serialize each scope once, except that `getAllMissing()` serializes a missed scope again for the memo write (accepted; a miss already costs a driver call). `getAllMissing()` returns early with no driver call when every pair is memoized. Reading one feature for one scope skips the preload, since the read loads it the same way.
- Default scope resolves per operation (auth may change mid-request).
- Feature-name resolution: `nameMap` key fast path; for class strings cache the resolved name (class → `#[Name]`/`$name`/class) in `$this->classNames`, updated when the class is defined and cleared by `setContainer()` (names come from container-built instances). Never cache misses for non-class input.
- Resolver metadata: only Closures and feature classes are resolvers; every other defined value is a constant, even when it looks like a callable or class name. `define()` records class-defined features in `$this->featureClasses` (name → class) and removes the entry for value definitions. `definedFeaturesForScope()` filters only Closures and `featureClasses` entries (reflected functions cached per feature in `$resolverFunctions`, cleared in `define()`); `implementationClass()`/`hasBeforeHook()` and `instance()` use `featureClasses` instead of guessing from `nameMap` values. No before-hook presence cache (`method_exists` on the recorded class is cheap); `get()` skips the hook path entirely when there is no hook. Whether a feature's before hook accepts a null scope is cached per feature in `$beforeHookAcceptsNull` inside the unchanged `resolveBeforeHook()` (a non-null hook result skips the driver, so the reflection would otherwise repeat every request); cleared for the feature in `define()` and entirely by `setContainer()`.
- Guard every event dispatch with `hasListeners()` (`FeatureRetrieved` still fires on memo hits when listened, e.g. Sentry). All Pennant event dispatch uses the `Event` facade (`Event::hasListeners()` / `Event::dispatch()`), as the Decorator does upstream; the drivers stop capturing a dispatcher. `Event::fake()` only refreshes the Model and Cache dispatchers, so a captured dispatcher misses fakes installed after a store resolves (stores usually resolve at boot, where features are defined).
- `typeAllowsScope()` matches builtin names with PHP predicates (`mixed`, `object`, `iterable`, `callable`, `array`, `string`, `int`, `float` accepting int, `bool`, `true`, `false`), resolves `self`/`parent` against the declaring class, and uses `instanceof` for classes; a `null` scope still defers to `canHandleNullScope()`.

## Partitioning

`FeatureManager::resolvePartitionUsing(string $column, Closure $resolver): void` (Boot-only, instance state; survives `forgetDriver()`). Throws `RuntimeException` if any store is already resolved: an earlier store holds no partition resolver and would read and write across partitions. `$resolver(string $store): int|string|null`. Column validated as a simple SQL identifier (same regex as `PermissionRegistrar::resolvePartitionUsing()`).

- Store config `'partitioned' => false` opts a store out (central flags; tenancy central surfaces have no tenant). Default: partitioned when a resolver is registered. Documented, not in shipped config.
- `FeatureManager::resolve()` builds a `?Closure(): FeaturePartition` per store (protected `partitionResolver($name, $config)`, mirroring upstream's `defaultScopeResolver($driver)`; null when unpartitioned) and passes it to the Decorator and the built-in drivers. Each layer calls it once per operation and passes the captured result down: `DatabaseDriver` keeps upstream's no-argument `newQuery()` as the base table query and adds `newPartitionQuery(?FeaturePartition)`; its read, insert, write and invalidation helpers take the partition. `ArrayDriver::get()`/`getAll()` share a protected `retrieve($state, $partition, $feature, $scope)` that writes through the captured state. `FeaturePartition` (`src/FeaturePartition.php`, readonly `column`, `value`). Its `key()` length-prefixes the column and `(string) $value`, so `1` and `'1'` (the same SQL partition) share memo and cache identity, as `PermissionPartition::encodeCacheSegment()` does; unpartitioned stores use `''`. A `null`/`''` value throws `Exceptions\FeaturePartitionNotResolved` (fail closed).
- The Decorator memo always includes the partition key. Custom drivers scope their own storage (documented).
- Applies to every driver operation: reads, first-resolution inserts, upserts, deletes, `stored()`, `purge()`, `setForAllScopes()`, `pennant:purge`, array values, memo, shared-cache identities. `globally()` stays a scope inside the partition. Cross-partition maintenance uses the integrating package (e.g. tenancy `runForEach`), not a bypass API.
- Partitioned schema is app/package-owned (like Permission): partition column non-null, unique `(partition, name, scope)`.

## Configuration

```php
'stores' => [
    'array' => ['driver' => 'array'],
    'database' => [
        'driver' => 'database',
        'connection' => null,
        'table' => 'features',
        'cache' => null,
    ],
],
```

- The section comment explains `cache` (`store`, optional `ttl` seconds). The default TTL is stated in `pennant.md`, not the config comment, so there's no comment-vs-constant test.
- `FeatureManager::getDefaultDriver()` reads `config->string('pennant.default')` (no `?? 'database'`). Config via named methods (no `ArrayAccess`).
- Database factory normalizes once: `connection` (`null` or `''` → `null`, the runtime default, as `DatabaseManager::connection()` treats them), `table` (optional, default `'features'`), `cache` (`store` required when present; `ttl` defaults to `StoredValueCache::DEFAULT_TTL = 3600` and must be a positive integer, since the repository treats `null` as forever and non-positive values as deletes, and the finite TTL bounds staleness).
- Stores read their config once, when built (upstream laravel/pennant#81 rereads the database store's `connection`/`table` on every query so a store kept across Octane requests follows config edits). Config is process-global in Hypervel, so request-time edits aren't supported: per-request connections use a `connection => null` store with `DB::usingConnection()`, shared tables use partitioning. After boot/test reconfiguration of store definitions, call `forgetDrivers()` (not just the changed store: other resolved stores captured its cache profile as an invalidation target), then define features again (rebuilt stores start with no definitions). No config watchers or rebuild machinery.
- `connectionName()` rejects a `::read` connection, whether configured or the runtime default (`DB::usingConnection('mysql::read', ...)`), before any memo, cache or SQL access: Pennant writes on first resolution, and with read config `DatabasePool::connectionRole()` sends every operation on a read alias to the replica.
- Invalidation targets (config-only, at factory): the distinct `cache` profiles of every configured `database` store on the same table whose connection overlaps this one (`null` overlaps every connection, since `DB::usingConnection()` can select any; explicit names compare after `withoutWriteType()`), including its own. Mutations rotate tokens in every target, so writes through an uncached or differently cached alias still invalidate cached readers. Rejecting overlapping stores with different cache config instead would always throw, because `stores` merges by name and the default uncached `database` store stays configured. Docs: physical aliases under different connection names must use one canonical name.

### Schema (`database/migrations/2022_11_01_000001_create_features_table.php`)

```php
Schema::create('features', function (Blueprint $table) {
    $table->id();

    // MySQL and MariaDB string collations ignore case, accents and trailing spaces.
    if (in_array(Schema::getConnection()->getDriverName(), ['mysql', 'mariadb'], true)) {
        $table->binary('name', length: Builder::$defaultStringLength * 4);
        $table->binary('scope', length: Builder::$defaultStringLength * 4);
    } else {
        $table->string('name');
        $table->string('scope');
    }

    $table->text('value');
    $table->timestamps();

    $table->unique(['name', 'scope']);
});
```

`Builder` is `Schema\Builder` (`DEFAULT_STRING_LENGTH` is protected; the public static keeps any app override). The migrator sets the migration's connection as the coroutine default, so `Schema::getConnection()` is the target. `VARBINARY(1020)`: 2,040-byte unique key, under InnoDB's 3,072 limit; PHP receives plain strings. PostgreSQL (deterministic collation) and SQLite (BINARY) already compare exactly. The migration keeps extending the unchanged `PennantMigration`.

### Reads (`getAll`)

Constants: `QUERY_GROUP_LIMIT = 500` (half SQLite's default `SQLITE_MAX_EXPR_DEPTH` 1000; verified 990 OR groups pass, 1000 fail), `QUERY_BINDING_LIMIT = 10_000` (under SQLite 3.32's 32,766; partition binding counted), `WRITE_ROW_LIMIT = 1000`.

1. Dedupe canonical `(feature, serialized scope)` pairs, keeping caller positions; skip features with empty scope lists; no query when nothing remains.
2. Group features by their sorted, length-prefixed scope-key list (hash map; O(S log S) sorting).
3. Split a group exceeding the binding limit by scope (then feature) chunks; pack groups greedily into statements under both limits.
4. Each statement: `select name, scope, value ... where [partition = ? and] ((name in (...) and scope in (...)) or ...)`, the OR chain always inside a nested `where` (a top-level `orWhere` would escape the partition). Index rows by exact `[name][scope]` (no `Collection::where()` loose `==`, which matches `'01'` to `'1'`).
5. Read connection: normal read PDO; write PDO when the store publishes to its own cache (a replica-lagged value must not be published under a post-rotation token).

A rectangular `load()` (F features × S scopes) is one group and F+S bindings.

### First resolution

For missing pairs: resolve (unknown features → `false`, not stored, `UnknownFeatureResolved`), then insert candidates in `WRITE_ROW_LIMIT` chunks:

- PostgreSQL, SQLite: `insertOrIgnore($rows)`. PostgreSQL compiles `ON CONFLICT DO NOTHING` (only unique/exclusion conflicts are skipped). SQLite's `INSERT OR IGNORE` also skips NOT NULL/CHECK violations, but Pennant supplies every non-null column and the schema has no CHECK constraint; a row skipped by an app-altered schema still surfaces through the reread, retry and exception below. The SQLite no-op upsert is not used because SQLite counts its duplicate rows as changes (verified on 3.45), which would force a reread on every first resolution.
- MySQL, MariaDB: `upsert($rows, $uniqueBy, ['name' => new Expression($query->getGrammar()->wrap("{$table}.name"))])`: a table-qualified no-op (`wrap()` applies the table prefix; the unqualified form is ambiguous on PostgreSQL, 42702). `INSERT IGNORE` would silently truncate over-long values in strict mode.
- If affected rows equal the candidate count, every candidate won: return them (the uncontended path keeps upstream's one select plus one insert). Otherwise, or on MySQL/MariaDB when FOUND_ROWS may be on (no-op duplicates then count as affected), reread. FOUND_ROWS is known off only when no `db.connector.{driver}` binding replaces the built-in connector (built-ins are created fresh with fixed defaults) and the connection's `options` don't set `Pdo\Mysql::ATTR_FOUND_ROWS`; a bound custom connector always rereads. The reread fetches the candidate batch through the grouped read path from the write PDO and returns the decoded stored values (a winner whose JSON matches the candidate's doesn't prove the candidate won, and its PHP form can differ). Only MySQL/MariaDB add `sharedLock()`: a REPEATABLE READ snapshot can't see the winner without a locking read, while PostgreSQL READ COMMITTED rereads see it and stricter levels fail on the insert.
- Pairs still missing after the reread (concurrent purge/delete) are re-resolved and retried, at most 2 times per operation (local loop variable), then `RuntimeException('Unable to insert feature values into the database.')`. Never return a candidate not known to have won.
- PostgreSQL REPEATABLE READ/SERIALIZABLE serialization failures propagate (the caller's transaction must restart).

`get()` returns `getAll([$feature => [$scope]])[$feature][0]`, so the single-pair path shares the same insert, retry budget and message (upstream's separate one-retry path and singular message go away; its query counts are unchanged).

### Mutations

- `set` / `setAll`: `upsert` keyed by `[partition,] name, scope`. `setAll` first collapses duplicate `(feature, serialized scope)` pairs, keeping the last value like the sequential fallback (PostgreSQL rejects an upsert that updates one row twice), then chunks; multi-chunk runs inside one transaction.
- `setForAllScopes`, `delete`, `purge`: single statements with the partition predicate.
- With invalidation targets, via `$connection->afterCommitOrNow()`: `set`/`delete` rotate the scope token, `setAll` rotates its distinct scope tokens with one `putMany` per target, `setForAllScopes`/`purge` rotate the partition token. Every target is attempted; the first ordinary failure is rethrown after the loop, while `CanceledException` passes through at once (the `executeCommitCallbacks()` pattern).

## Shared cache (`src/Drivers/StoredValueCache.php`)

Opt-in per database store. Caches stored row values only (never `before()` results, never unknown-feature `false`). Database stays authoritative; eviction never rerolls an assignment. Built by the factory when the store has its own `cache` or any invalidation target: it reads and publishes through the store's own cache (if any) and rotates tokens in every target.

Identity: `ConnectionName::withoutWriteType($requested)` + table + partition key (no store name; aliases on one cache store share entries and invalidation). Keys use length-prefixed raw segments (no hashing; process-seeded hashes can't be shared through Redis):

```text
P            pennant:{storage}{table}{partition}:p              → partition token
S(scope)     pennant:{storage}{table}{partition}:s{scope}       → scope token
V(f, scope)  pennant:{storage}{table}{partition}:v{scope}{f}    → ['p' => token, 's' => token, 'v' => stored JSON text]
```

`v` holds the row's `value` column text (or the JSON just inserted), and hits decode it exactly like rows (`JSON_OBJECT_AS_ARRAY | JSON_THROW_ON_ERROR`). Later requests therefore get the database representation (arrays, `1` not `1.0`) while the first resolution still returns the resolver's own value, as upstream does. Tokens are `(string) Str::ulid()`, never counters, so an evicted token is never reused. Tokens and values use the profile's TTL.

Read (memo misses only; skipped entirely while `DatabaseManager::hasApplicableTransaction()` is true):
1. One `many()` for `[P, S(scope)…, V(pair)…]`; an entry is valid when `v.p === P && v.s === S(scope)`. Tokens are operation-local (not memoized).
2. Missing tokens: generate and `putMany` them before the database read; if that returns `false`, skip publishing for this operation.
3. Database path for the remaining pairs (reads, first resolution).
4. `putMany` stored/winning values under the tokens captured in step 1.

A fill that captured tokens before a writer's commit publishes under rotated-away tokens, so readers ignore it: no locks, tombstones or CAS. Rotation `put` exceptions propagate; a `false` return throws `RuntimeException` (invalidation failed after commit; cached values may be stale until TTL). Oversized values follow normal cache errors (`ValueTooLargeForColumnException` on Swoole layers); no chunking.

Docs: TTL bounds staleness after a crash or failed write between commit and rotation; with a stack store the Swoole layer's TTL bounds cross-server staleness; use a Redis store for prompt changes.

## Upstream fixes (each with a regression test)

1. `ArrayDriver::get()` `isset` treats stored `null` as missing → `array_key_exists`.
2. `typeAllowsScope()` rejects valid scopes for `object`, `iterable`, `callable`, `self`/`parent`, `float` (int scopes are allowed under `strict_types`) and standalone `true`/`false` → matcher under Hot path. Keep union/intersection/nullable handling. Fix "encoutered" typo.
3. `getAll()` loose matching (`'01'` vs `'1'`) and duplicate scopes producing duplicate inserts (fixed by Reads steps 1 and 4); duplicate `setAll()` pairs failing on PostgreSQL (fixed under Mutations).
4. `loadAll()` uses only `scope()[0]`'s features for every scope (mixed `User`/`Team` scopes pass a `Team` to user-only resolvers). Compute valid features per distinct scope and submit one sparse batched `getAll()`, keeping each scope's original position as its key.
5. Keyless models: `serializeScope()` throws `RuntimeException` for a `Model` with a null key (after `FeatureScopeSerializeable`). Assign a key or pass an explicit string/serializable scope.
6. Exception-driven insert retry (shared `$retryDepth`, PostgreSQL transaction abort on unique violation) → First resolution.
7. Rolled-back values remaining in the memo → transaction tracking.
8. Constant values that look like callables or class names (`'next'`, `[$object, 'method']`, `SomeClass::class`) are treated as resolvers by `definedFeaturesForScope()` (dropped from `all()`/`loadAll()` when the signature rejects the scope), `hasBeforeHook()` and `instance()` → resolver metadata under Hot path.

Unexpected-null fallback stays persisted (Pennant persists first outcomes); docs say to `forget()`/`purge()` after changing a definition.

## Framework changes

1. **AGENTS.md** (*Code conventions*), replace the semantic-column bullet with:
   > **Use semantic column types in migrations** — `uuid()` / `foreignUuid()` / `uuidMorphs()` for UUIDs, `ipAddress()` / `macAddress()` for network addresses, and `jsonb()` for JSON the database queries, indexes or validates. Use `text()` for opaque serialized values that are only read back whole. PostgreSQL gets the real types (`jsonb`, `uuid`, `inet`, `macaddr`); the other supported databases fall back automatically to compatible types.
2. **`StackStore::many()` / `putMany()`** batch per layer. Both currently loop per key, so a cold Pennant batch on a Swoole + Redis stack costs one Redis round trip per key. `StackStoreProxy` already forwards `many()`/`putMany()` (with its layer TTL clamp).
   - `many()`: call each layer's `many()` top-down for the keys still missing, with `getOrRestoreRecord()`'s rules (any non-null record ends that key's search; a lower record is backfilled into the layers above only when it has `value`). Backfill uses `putToStore()`'s normalization (absolute expiration kept, records without expiry use `forever()`), grouped per destination layer by remaining TTL into one `putMany()` per group; the proxy still applies layer TTL caps. Return values in input order.
   - `putMany()`: normalize records once and call each layer's `putMany()` once. If a layer returns `false` or throws, stop and compensate by forgetting the batch keys from the completed layers and the failing one (deepest-first, same cancellation handling as `callStores()`), then return `false` or rethrow. The failing layer is included because a layer's `putMany()` can write some keys before failing. Compensation is best-effort invalidation; it doesn't restore earlier values.
   - Update `CacheStackStoreTest`'s `testMany`/`testPutMany` expectations to the batched calls. `testPutManyReturnsFalseForFailedKeyAndAttemptsLaterKeys` becomes a batch-failure compensation test (per-key partial success is gone). Add tests for partial hits per layer with batched backfill and preserved expiration, and lower-layer failure compensation.
3. **Sentry**: port `PennantPackageIntegration` (keeps upstream name) to `src/sentry/src/Features/`. Upstream injects the dispatcher into `onBoot(Dispatcher $events)`; Hypervel's `onBoot()` takes none, so resolve `events` from `$this->container` as `CacheIntegration` does. `isApplicable()` checks `class_exists(Feature::class)` (like `AiIntegration`). Add it to the shipped `features` list, port the upstream test to `tests/Sentry/Features/PennantPackageIntegrationTest.php`, mention feature flags in the Sentry docs introduction, and remove the Pennant item from `docs/todo.md`.
