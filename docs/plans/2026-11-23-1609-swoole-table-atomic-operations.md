# Use native Swoole Table operations in shared framework state

## Scope and guarantees

Adopt the single-row operations from [swoole-src#6126](https://github.com/swoole/swoole-src/pull/6126) in the Swoole cache, Reverb shared state and Swoole rate limiter. Fix collision-chain flushes, stale eviction decisions, connection-slot admission and capacity failures on the affected paths. Keep existing public methods, parameter names, return types, schemas, config, cache events and backend selection. Stack cache delegates to stores and its bottom lock provider. The private packages and apps have no corresponding production Table implementation.

The framework requires `^6.3.0RC2`. All five methods shipped in RC1. Each operation checks and mutates one physical key under its native bucket lock. Missing and logically expired rows are different. Pass values read from the table back as expected columns. Numbers compare by native bytes and strings by length and bytes. Use PHP for TTL and ownership decisions. Relevant upstream code is in the [RC2 binding](https://github.com/swoole/swoole-src/blob/v6.3.0-rc2/ext-src/swoole_table.cc) and [native table](https://github.com/swoole/swoole-src/blob/v6.3.0-rc2/src/memory/table.cc).

## Cache

Implement in `src/cache/src/SwooleStore.php`. Keep ordinary writers and cleanup under their existing row stripes. Both flushes hold every stripe across **collection and deletion**. Live reads and hit accounting remain outside the barrier.

- **Flush.** Collect only eligible keys, finish iterating, then call `rawForget()` on them. Deleting during Swoole’s positional collision-chain traversal shifts the next row and can leave entries behind even with one worker. `flush()` deletes every non-control key, including legacy keys. `flushLocks()` deletes only lock keys and retains its separate-lock-store check. Share the two-pass traversal between the two methods.
- **Hits and expiration.** Record LRU hits with `update($key, ['last_used_at' => ...])`. LFU still needs a native increment. Use `@$this->table->incr($key, 'used_count', 1)` for this best-effort statistic. A concurrent delete can still leave an expired shell. Allocation failure while updating a statistic must not discard an already-read hit. In store `add()` and `touch()`, read just `get($key, 'expiration')` under the stripe, distinguish strict `false` from a timestamp, and treat equality with now as expired. Preserve live-duplicate rejection before the checked write, serialization outside the stripe in `add()`, partial-column update on a live touch, and post-write eviction outside the stripe.
- **Stale cleanup.** Give `forgetExpiredRecord()` the observed expiration from `get()` or the maintenance scan. Under the stripe call `cmpdel($key, ['expiration' => $expiration])`. For lock rows, establish expiry using the decoded payload as today, retain the original serialized `value`, and compare that exact value under the stripe. A renewal or replacement must survive. Keep scans and deletes in separate passes. Retain only key and comparison value for each stale row, cast numeric-looking array keys back to strings when passing them to typed methods, and keep the non-lock control exclusions. The interval miss path may have written a live cached null between the original read and cleanup.
- **Eviction.** Keep the bounded heap and its compact fingerprint. In `forgetEvictionCandidate()`, keep the striped reread and fingerprint comparison, then `return $this->table->cmpdel($key, $record);` using the complete reread row. This catches a lock-free hit between rechecking and deleting. Retaining full serialized values throughout the heap increases memory use precisely when the table is under pressure.
- **Capacity.** After `add()` or `acquireLock()` has established eligibility, a failed write is an operational failure. A conditional add returning false is used as an existing marker by the queue worker, and `Lock::block()` retries false as contention. A counter must only return a number after storing it. Use a store-local write-or-throw helper for these three operations. Pass the logical cache key (or lock name) alongside the hashed table key. Suppress the native allocation warning only on this helper’s call to `rawPutSerialized()` so both warning modes reach the same capacity diagnostic. On strict false, throw a `RuntimeException` naming the logical key, explaining that the Swoole cache table is full and pointing to `rows` and `conflict_proportion` in `cache.swoole_tables`. Let native exceptions propagate. In `increment()` compute the value and expiry in the existing branch (permanent on missing/expired, preserve exact expiry on live), then write once. `decrement()` delegates. Preserve class-disabled counter deserialization. Ordinary `put()`, `forever()`, their batch callers, and interval writes keep their existing handling of thrown errors and false results. Failover advances on exceptions. Globally translating them to false would disable that path. Preserve the checked string payload write through `Cache\SwooleTable::set()`. Its new Table calls only update a float or compare columns for deletion.
- In the Swoole Table Cache section of `src/docs/cache.md`, briefly distinguish a live duplicate or held lock from failure to allocate a row. Document counter write failures and the one-second wait limit for writes and expired-item cleanup during a flush.
- Keep interval registration, claims, resolver execution and index coordination. Replace the whole `SwooleTableState` class docblock, including its outdated premise and TODO, with one sentence explaining that the stripes serialize compound mutations and allow flush to hold writers back. Update the stale-recheck and hit comments to match the new behavior.

## Reverb

Work in `src/reverb/src/Servers/Hypervel/Scaling/SwooleTableSharedState.php`. The webhook table holds timestamps for independent keys. The counter table holds subscription, presence and connection counts. Only the latter needs PHP stripes.

**Distinguish insert outcomes.** On RC2, duplicate `add()` returns false and leaves the last Swoole error alone. Exhaustion sets `SWOOLE_ERROR_PHP_RUNTIME_NOTICE` and returns false, or emits a warning converted to `ErrorException` by Hypervel. `swoole.display_errors=0` silences this warning independently of PHP’s error handler. Use one Reverb-local insertion helper returning `?bool` for the two tables. Its callers supply bounded hashed keys and known numeric columns and values. No callbacks or yielding operations belong between clearing the error and inspecting it. [Native error macros](https://github.com/swoole/swoole-src/blob/v6.3.0-rc2/ext-src/php_swoole_private.h)

```php
// true = inserted, false = already present, null = no capacity
swoole_clear_error();

if (@$table->add($key, $values)) {
    return true;
}

return swoole_last_error() === SWOOLE_ERROR_PHP_RUNTIME_NOTICE ? null : false;
```

- **Smoothing markers.** Both setters write the timestamp directly via the shared marker-write path. Honor the boolean from `@$this->lockTable->set(...)` and report the existing `lock_rows` diagnostic on failure. `consumeMarker()` uses `getdel($key, 'locked_at')`, returns false on absence, and applies the existing age test to the removed timestamp. Age equal to the TTL is expired. Both explicit throttle clears use direct `del()`.
- **Throttle and dedupe.** In `tryLock()` read just `locked_at`, then sample the current time. A live timestamp returns false after one read. On absence use the insert helper. Return true on insertion, log once and return false on exhaustion, reread on a duplicate. For an expired timestamp use `cmpset($key, ['locked_at' => $observed], ['locked_at' => $now])`. Success acquires it. Reread with fresh time on mismatch because a competitor may have either renewed or cleared it. This avoids suppressing a webhook after a concurrent clear and avoids retrying on a full table.
- **Subscription counters.** Keep the ordered channel/user stripes through both presence reservations and increments. `ensureRowExists()` uses the insert helper with count zero, returning whether this call created the row and throwing the existing main-table capacity diagnostic on null. If the user reservation fails, roll back only a channel row created by this operation. The transition flags determine which connection publishes occupied/member-added events. Independent increments can split those flags between two subscribers even when the final counts are correct. An empty presence user ID takes the single-channel path, which must honor the same channel stripe.
- **Increment and decrement.** A single native `incr()` initializes a missing count. Use a shared increment helper that requires the caller to hold the stripe and only performs the native operation and capacity check. The ordinary single-channel subscribe acquires its stripe around that call. Presence subscribe calls the helper for each key inside its existing two-stripe section, and slot admission calls it inside the app stripe already held for the cap check. Reacquiring a held stripe would time out. For the known integer column use `@$this->table->incr($key, 'count', 1)` and translate strict false to the main-table `RuntimeException` naming the `rows` config and physical key. Reuse that diagnostic for presence allocation. For decrement under a held stripe, return zero if absent. Otherwise decrement, delete at zero or below and return the count. Use this logic for ordinary unsubscribe, each half of presence unsubscribe under its two stripes, and slot release. Remove allocation/preflight on unsubscribe. Preserve the existing flags and the clamped public count.
- **Connection slots.** Hold the app key’s stripe once. Read `count` (absence means zero) and reject at or above the limit before writing. Otherwise increment while still holding that stripe and return true. Previously a rejected admission incremented and rolled back in two critical sections, so another request could be refused after the only active connection had released its slot. Keep the public signatures and failure diagnostic. Remove redundant lock wrappers and stale descriptions after checking their callers.

## Rate limiter

In `src/rate-limiter/src/SwooleStore.php`, retain the same stripes for the full group, single-key operations, inspection and pruning. A failed group can roll back earlier writes. Reading them before rollback can cause a false throttle denial.

1. In `consumeMany()`, read each distinct physical key once under the group locks. Derive presence from strict `$row !== false` and feed the same raw row to the existing numeric-state validation. Factor the conversion from `array|false` to the three integers so single-key `storedState()` and grouped reads share it. Keep ordered policies, repeated-key charges, numeric-string key handling and the original state for rollback. A present all-zero row and an absent row need different rollback actions.
2. In `writeState()`, use `@$this->state->table()->set(...)` for the framework-generated key and three fixed integers. The method already returns bool and all four mutation paths handle false. With normal framework warning conversion, exhaustion previously threw before rollback. The existing false path restores earlier writes under the group locks, prunes outside them, retries once and throws `SwooleTableFullException` if capacity is still exhausted. Keep input validation and exception handling outside this individual native call.
3. In `pruneExpiredRows()`, collect the positive integer `expires_at` and key for each row expired at scan time. After iteration, under each key’s stripe, count successful `cmpdel($key, ['expires_at' => $observed])` calls. Use string keys when passing numeric-looking PHP array keys to the typed API. An identical expired deadline remains eligible. A renewed deadline survives. The stripe prevents rollback from resurrecting a row pruned during a group write.

For example, the grouped read can use the existing state map to recognize duplicate keys before touching the table:

```php
if (! isset($states[$key])) {
    $row = $this->state->table()->get($key);
    $existing[$key] = $row !== false;
    $states[$key] = $this->parseStoredState($row);
}
```

Class-level `@method` declarations work through the existing `HypervelStubFilesExtension`. Declare `add($key, $values)`, `update($key, $values)`, `cmpset($key, $expected, $values)`, and `cmpdel($key, $expected)` returning bool, and `getdel(string $key, ?string $field = null)` returning a row, int, float, string or false. Use the native parameter names and types, PHPDoc array element types for column maps and a single explanatory sentence in the stub. Use `array<array-key, mixed>` for writes (numeric keys are ignored), `array<string, mixed>` for expected columns, and `array<array-key, float|int|string>|false|float|int|string` for the `getdel` result. Production analysis exercises every signature.
