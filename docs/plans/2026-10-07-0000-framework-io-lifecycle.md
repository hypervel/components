# Framework I/O lifecycle and supporting APIs

## Completed scope

This plan records the framework work completed in [PR #653](https://github.com/hypervel/components/pull/653), now part of `0.4`. It contains the extracted database/HTTP checkpoints and supporting framework changes; it is not a remaining-work list for the [AI SDK package port](2026-10-07-ai-sdk-port.md). The sections below preserve the implementation requirements and acceptance criteria. Open dependency integrations remain tracked in `docs/todo.md`.

The work addressed database sessions held during long external waits, incremental HTTP delivery, cancellation and cleanup, and shared-state correctness. It applies to ordinary API calls and other long-running requests as well as AI. Framework APIs retain familiar behavior; deliberately session-dependent operations spanning automatic release use `withPinnedSession()`. The approved filesystem contract additions require custom implementations to provide the two existence methods.

Implementation was separated from the AI package into database ownership, HTTP streaming/cancellation, and supporting-framework review boundaries. Framework benchmarks and follow-up optimizations were completed before publication, except for the explicitly tracked native-readiness performance follow-up. The PR is the source for benchmark results and the complete change description; this plan retains the design and test requirements without repeating those results.

## 1. Database connection ownership

### Completed framework surface and downstream requirements

Logical connections now remain owned by their execution while physical PDO sessions can return to the pool between operations. Retained builders, sticky routing, logs and callbacks survive early release. Initial resolution still borrows a slot; later use reacquires lazily. Lifecycle, read-endpoint selection, physical-handle cleanup and transaction-context isolation fixes are implemented with regression coverage. See the source and database documentation for their internal details.

Use the additive operations:

```php
DB::releaseIdleConnections();

DB::withPinnedSession(function () {
    // Explicitly session-dependent operations may span external I/O here.
});
```

`releaseIdleConnections()` acts only on the current execution's existing connections. Transactions, cursors, complete query/event callbacks, scoped FK suppression and explicit pin scopes prevent voluntary release. Pins do not prevent replacing a broken session. `lazy()`/`chunk()` may release between completed batches. Retained raw PDO/statements or manually changed SQL session state spanning release require `withPinnedSession()`; ordinary builders do not. Existing session configurators synchronize on acquired physical sessions; this does not add transaction-pooler support.

`DB::extend()` drivers retain whole-connection ownership and early release is a no-op. The same applies when selectable records differ in driver, database or table prefix: write records for base pools, read records for `::read` pools. PDO-first custom drivers participate through `Connection::resolverFor()` and, when needed, `db.connector.{driver}`. Preserve concrete connection identities and these extension boundaries.

Read/write construction selects each endpoint once for both its PDO and configuration metadata. Explicit `::read` pools select records per physical connection, not once per worker; read records must agree on effective pool settings. Disconnect, replacement, failed preparation and SQLite bootstrap clear hidden PDO holders in discarded grammar cycles. Lease settlement preserves ownership through callbacks and clears lost resources before rollback callbacks can reconnect. A `ConnectionEstablished` listener's replacement PDO remains authoritative when the outer resolver resumes, including lazily replaced read connections.

Child coroutines own separate connections and transaction records. `DatabaseTransactionState` is non-copyable; Testbench explicitly transfers the same bag across setup/test/teardown. Normal child work does not inherit transaction ownership.

`ConnectionResolver::releaseIdleConnections()` is a static current-context operation; DatabaseManager delegates directly. The built-in Http handler releases after application request callbacks and fake selection, before destination-policy DNS or transport I/O, including retries and redirects. No container resolution or DB initialization occurs on this path. Caller-supplied clients bypass the framework handler stack and own their release boundary. `withPinnedSession()` is the scoped opt-out; there is no HTTP toggle or worker-global flag.

Callers release explicitly before parallel work and non-HTTP external waits, because children cannot release the parent's non-copyable lease. The database docs cover manual release before application `parallel()` calls; the coroutine package has no DB dependency. AI-owned release boundaries remain implementation work in the package plan.

Expand the database Connection Pooling subsection to “Releasing and Pinning Connections,” updating its anchor and links. Cover the default, manual release, named/default pinning, transactions, fan-out and a session-lock example with writer routing and finally cleanup. Cross-link Http docs and record the actual compatibility adaptation in the database README and porting guide. Test real automatic release while a loopback provider is silent, sibling pool access, lazy reacquisition, callback/retry/redirect boundaries, isolation and pin preservation; reuse existing ownership tests rather than duplicating their matrix.

### Database performance acceptance

In `tests/Benchmarks/Database`, compare ordinary request database lifecycles against the unchanged baseline: logical construction, first query, query pinning, acquisition/settlement and coroutine-end cleanup, at realistic concurrency. Include GC runs/collected/roots, heap growth between collections and worker peak memory alongside concurrency and request counts. Use alternating paired samples with identical runtime settings, reporting spread and medians. Measure pool waits and session hold times with a pool smaller than request concurrency, including early release and transaction-pinned cases. This redesign affects every database-using application. Require no unexplained throughput or allocation regression and optimize measured construction costs. Keep logical connections caller-owned: grammar cycles prevent weak references from distinguishing retained objects from uncollected garbage, so they cannot safely gate recycling. Comparative measurements require an owner-confirmed idle window.

## 2. HTTP streaming and response cancellation

### Incremental provider responses

The PHP stream path has two delivery problems: Swoole's buffered-read defect (fixed upstream in #6235 but absent from stable 6.2.x), and blocking chunked-response filtering when body data arrives after headers, reproduced with Swoole hooks disabled. Its default `Connection: close` also prevents keep-alive reuse. The incremental cURL route belongs to the HTTP transport and serves `Response::lines()`/`jsonLines()`. Fallback StreamHandler tests retain their applicable runtime skips.

Implement a pull-driven PSR response body using Guzzle's CurlFactory and one exclusively owned multi handle per active transfer. Pause receives at BufferStream's existing high-water mark and resume after draining, without selecting while buffered bytes remain. Share only the operation's scalar pause flag between sink and body; clear it before resuming because the sink can pause again synchronously. Reads return available bytes immediately, without waiting to fill the buffer. Bulk, slow-consumer and paced measurements assess buffering; final native-readiness-dependent measurements remain the follow-up below. This needs no producer coroutine and keeps callbacks in the calling execution. Integrate at `PendingRequest::buildHandlerStack()` and the factory's named-handler boundary, preserving middleware and caller-supplied handlers/clients. Preserve compatible fallback behavior for stream-only options or runtimes the new route cannot serve.

Named handlers retain at most 32 idle streaming transports, created only as needed, each with `CURLMOPT_MAXCONNECTS = 1`, without capping active requests or adding admission configuration. Reuse exact proxy-ownership signatures and evict the least recently used idle transport when full. Unnamed and asynchronous streams use operation-owned transports without worker caching. Honor configured transport-sharing modes and Guzzle's proxy-tunnel ownership signatures when reusing native connection caches; never retain per-request credentials or callbacks on idle handles. Document retained descriptor costs and validate equivalent verified-TLS performance and new-connection counts under bursty arrivals before the PR.

Buffered retention is tracked in [guzzle#3935](https://github.com/guzzle/guzzle/pull/3935): Guzzle's synchronous handler retains three idle easy handles, which is not a physical-connection bound. Adopt `max_idle_handles` once a release supports it through Guzzle's handler-selection API, reconcile supported dependency versions, then unskip `HttpConnectionTest::testNamedBufferedRequestsReuseConnectionsAcrossConcurrentBursts`. Do not duplicate Guzzle's routing, route buffered requests through streaming, or expose a general setting that buffered requests ignore.

**Native performance follow-up:** Swoole's hooked `curl_multi_select()` can consume ready data through `curl_multi_socket_all()` and then wait for another event or its timeout. Completion stalls and lost mid-stream readiness are reproduced on the cURL route. This does not block the framework PR or require a Hypervel workaround. Keep the implementation, omit unqualified buffering performance claims, and complete the regression/performance checks in `docs/todo.md` once a patched runtime is available. Add no polling, shorter select cap or pause-frequency workaround.

Support both declared Guzzle branches through their common factory/handle interfaces. Expose a final response after headers, ignoring informational responses except 101. When final cURL options enable origin/proxy authentication negotiation, wait for the first body write or transfer completion: intermediate 401 and even 2xx headers can precede an internally retried POST. Keep the header deadline through this decision. The retry callable passed to `CurlFactory::finish()` may restart only before exposure; never replay a published response. Invoke streaming statistics once at handler return, preserving callbacks in the caller's execution. A transfer completed before exposure delivers its trailers after successful `on_headers` processing and before statistics; preserve original callbacks across pre-header retries.

The receive callback holds a weak reference to its easy handle so Guzzle 7's discard behavior cannot leave a self-retaining callback cycle; the active transfer owns the handle. Abandoned-body tests verify prompt cleanup with cyclic collection disabled. Callback failures retain their response where applicable, and cancellation remains cancellation through Guzzle callback wrappers and routing exception conversion.

Required behavior:

- Bound buffering and idle retention; a slow consumer applies backpressure without unbounded queued events. Preserve streaming timeout semantics: `timeout` bounds the header phase, `connect_timeout` governs connection establishment, and `read_timeout` bounds idle gaps during headers and body reads, resetting on native readiness. The cURL route uses one 60-second idle default; explicit zero disables that limit. Document the older Guzzle fallback's context-timeout behavior. Do not cut long streams off using a transfer-wide deadline inherited from buffered requests.
- Per-request headers, credentials, cookies, body and middleware remain operation-owned. Reused physical transports must not retain request secrets/callbacks; dynamic origins must not create an ever-growing worker registry.
- Correct headers/informational responses, redirects, decompression, TLS verification, timeouts, middleware/fakes, stats and errors. Preserve supported options through the streaming handler or a compatible fallback; do not silently ignore them or reject existing usage without approval. Update transport capability guards, including the current `allow_url_fopen` check, to reflect the actual handler requirements.
- EOF, explicit close, exceptions, cancellation and abandoned consumption settle resources once. Sequential consumption may move to another coroutine after the creator ends. A disconnect cancels the coroutine currently blocked on provider I/O; its cleanup removes and settles the transfer. Do not assume removing a handle from another coroutine wakes a blocked read. Preserve pre-header errors and truncated-body errors instead of translating them to successful EOF.

### Caller disconnects on released runtimes

`IterableStreamedResponse::cancelOnDisconnect(bool $cancel = true): static` provides response-level opt-in. Registration covers response production in `ResponseBridge` and ends before terminable work. It does not cancel unrelated controller side effects, background jobs or every request globally. Enabling it on AI responses remains in the package plan.

Where existing Swoole connection-close delivery is reliable, compose internal handling with the configured application callback at `Server::registerSwooleEvents()`. Preserve the application callback even if internal cleanup encounters an error. Register only in supported effective modes, avoiding Swoole startup warnings. Group active registrations by connection and key them by producing coroutine, retaining the stream ID on each registration. This preserves concurrent pipelined HTTP/1 producers sharing stream ID zero. Cleanup removes only its own registration; full connection close cancels every opted-in owner on that connection. Keep the map bounded by active responses and retain stream identity for the future server-level stream-cancel event.

Current Swoole `RST_STREAM` handling has no PHP notification. A reset of one HTTP/2 stream while the provider is silent therefore remains detectable only by a subsequent failed write or operation completion/timeout. Document and test existing-runtime behavior honestly. The missing native capability is a server-level stream-cancel event identifying the connection and stream; a per-response native subscription is unnecessary. Keep this enhancement in `docs/todo.md` and integrate the actual released API when available; no per-stream polling, synthetic heartbeat solely for detection or dependency on an unaccepted/unreleased API.

Extend the existing `HttpClientStreamingTest`, `HttpClientResponseStreamTest` and related client/server suites using isolated loopback origins: paced SSE, split CRLF/UTF-8 lines, JSON lines, trailers, 1xx responses, truncated body, failures before headers, quiet upstream, slow consumer, explicit close and abandoned iteration. Assert cleanup and sibling-request progress under cancellation. Cover ordinary application close callbacks, opt-in boundaries and supported server modes; HTTP/2 reset tests must reflect the documented current limit. Reuse and extend this worktree's streaming fixtures rather than introducing duplicate test servers.

Explicitly prove that cancelling response production interrupts the new transport while waiting on a silent provider, both before headers and during a quiet body. Synchronize the fixture without depending on a later provider chunk or timeout to unblock it. Assert that the transfer closes and settles while sibling requests remain usable. Cover creator-to-consumer coroutine handoff, bounded backpressure, idle reuse, proxy credential isolation, digest POST negotiation, and body reads continuing past the header timeout. Exercise connection-close cancellation through ResponseBridge as well as direct transport cancellation; merely observing a flag or dropping a generator is insufficient.

Add deterministic PHP-stream fallback regressions for Swoole's concurrent response-header retention and Guzzle's shared request deadline ([guzzle#3934](https://github.com/guzzle/guzzle/pull/3934)). Demonstrate failures before applying the owner's skips: `SWOOLE_VERSION_ID <= 60203` for Swoole, Guzzle major version >= 8 for the deadline defect (run on 7). Update the Guzzle version gate once a fixed release ships. Mark the pending upstream fixes with concise TODOs and add exact test names to the dependency handoffs. Use synchronized loopback fixtures and an isolated subprocess for retained-memory measurement; no dependency patches or production workarounds.

The native cURL regression `CurlStreamingHandlerTest::testNativeWaitReportsDataArrivingBetweenPerformAndSelect` synchronizes a loopback origin with the transport's exec/select sequence. Keep the same owner-selected Swoole version gate and TODO, and its exact name in the native dependency handoff; this test covers the cURL route, not the PHP-stream fallback.

## 4. Verification, documentation and performance

Run each changed/new test file immediately, then affected suites. For final broad framework changes use the required full verification workflow (`composer fix` where appropriate, including `composer test:parallel`); run `composer test:testbench` after Testbench changes. PHPStan checks source, not tests. External-service tests use existing isolation/skip traits and are added to the correct service workflows; real database locking tests cover MySQL/MariaDB/PostgreSQL and relevant SQLite behavior. Redis Cluster suites follow their serial isolation rules. Local loopback fixtures use assigned ports, bounded waits and unconditional cleanup.

Supporting tests cover the filesystem contract/decorators, ObjectType's original property objects, bounded class-trait metadata and cleanup, scoped-context semantics, watcher root/directory events, and nested Testbench environment restoration. Use existing static-state cleanup, isolated local fixtures and real supported database coverage. Verify split-package dependencies, response contracts/facades and server adapters alongside source changes.

Maintain canonical database, HTTP client, response, filesystem, JSON schema and watcher documentation in `src/docs/`. Record actual compatibility adaptations in the relevant README and porting guide; do not repeat internal fixes as public API differences.

Use `tests/Benchmarks/HttpTransport` alongside the database harness. Measure cold/warm verified-TLS separately, paced/unpaced streams, slow consumers, first-event/completion latency, actual concurrent transfers, CPU, RSS/heap, descriptors, pool waits/hold durations, retained connections and long-running cleanup. Keep runtime, TLS, workload and retention settings identical in alternating comparisons. Preserve raw reports outside the repository. Functional tests use synchronization, not brittle throughput thresholds.

Keep database lifecycle CPU cost distinct from pool-constrained throughput gains and HTTP/TLS setup costs. An extra 10 µs/request at 10,000 requests/second is 0.1 CPU core. Prior mechanism probes mixed TLS/setup conditions and load; use controlled measurements for published claims. The merged PR records the verified automatic-release and streaming-retention results. Native readiness-dependent buffering measurements remain a `docs/todo.md` follow-up; add no workaround and make no unqualified buffering speed claim before that check.

Acceptance requires no leaked request state, orphan transfers or leases, unbounded worker caches, avoidable round trips, or unexplained throughput/memory regression. Optimize measured costs at their owning layer without weakening public behavior, TLS verification or correctness.
