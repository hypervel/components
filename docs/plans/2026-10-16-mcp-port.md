# Laravel MCP package port

## Outcome and boundaries

Port the complete Laravel MCP server and client package to Hypervel: tools, resources, prompts, completions, tool search, Apps, HTTP and stdio transports, protocol negotiation, OAuth, testing APIs, commands, configuration, assets, fixtures and documentation. Preserve the upstream public and protected API, named arguments, custom transports and extension points. Add coroutine-safe ownership and fix the verified defects below at their owning boundaries.

Implementation target: src/mcp with namespace Hypervel\Mcp, on the feature/mcp branch in the components-mcp worktree. The worktree has independent Composer dependencies and its own local test .env. This document specifies the design; the [remaining-files list](2026-10-16-mcp-port-files.md) tracks pending files. Remove finished entries rather than recording execution history.

The behavior changes below have owner approval. Do not commit, push or publish without owner authorization. During implementation, use the repository's checkpoint verification and review workflow; do not treat design consensus as code approval.

### Approved behavior changes

The proposed transport capabilities and Request::isObject() are additive; no existing method signature or contract is removed. Preserve Server::send() overrides and both existing HttpTransport::stream() callback forms.

The owner has approved these behavior changes:

1. Enforce the protocol's Origin check using the trusted application origin and an explicit additional-origin list. Developers/operators configure permitted origins for direct cross-origin browser connections; end users need no browser or CLI configuration changes. Validation uses in-memory comparisons, not DNS, network calls or database queries.
2. Apply Passport's existing named `passport` limiter to MCP dynamic registration.
3. Stop modern HTTP stream production on disconnect while retaining legacy completion behavior.
4. Remove the Inspector's automatic TLS-verification disablement; locally issued certificates need normal trust configuration or an explicit developer-controlled environment setting.
5. Restrict LastModified attributes to the complete date-time format specified under Errors and inputs. This prevents TypeScript-SDK clients from rejecting whole results and requires reformatting other previously accepted ISO 8601 representations.

These are correctness/security changes, not permission to remove APIs. Any further public/protected API departure, unsupported-feature removal, database schema change or meaningful performance regression requires a separate concrete approval. No MCP database schema change is proposed.

## Ownership and request context

| State | Lifetime and storage |
| --- | --- |
| Registrar definitions and named-client factories | Worker-owned service state |
| Tool/resource/prompt services | Normal Hypervel container lifetimes; no blanket Transient marker |
| Request arguments, metadata, URI, source and library scripts | One invocation; CoroutineContext |
| Named clients | Current coroutine owner; non-copyable state holder |
| Negotiation and synchronization | One Client/Protocol instance |
| HTTP response body and parser state | One exchange, owned by the calling coroutine |
| Immutable attribute metadata | Existing bounded per-class caches |
| Selected resource for response cache hints | One ServerContext/message |

### Complete request snapshots

Request implements Hypervel\Contracts\Container\Transient, inherited by custom Request subclasses. Preserve the resolving(Request::class) callback and fill each resolved request from CoroutineContext under Request::class. Copy arguments, metadata, URI and the source string; resource template variables are already merged into the arguments. This matches the AI adapter's existing key and keeps explicit application bindings authoritative.

Use one narrow server helper for temporary request/library-script installation. Its consumers are Server::runMethodHandle(), ReadResource::handle() and nested ToolSearch::invokeTool(). Save and restore previous values, including absence. Keep the ordinary scope in runMethodHandle(), which the public testing API also calls directly. Expose library scripts through a context-reading binding under the existing mcp.library_scripts container key so published views still work.

- Establish context before eligibility, handler and schema callbacks that run inside the operation.
- Keep eager arrays as arrays. In particular, ToolSearch::invokeTool(): array cannot be changed into a generator by an is_iterable() shortcut.
- Wrap lazy Generator/Traversable results, restoring the eager call's context before returning the wrapper.
- At iteration start, capture the consuming coroutine's previous state, install the operation snapshot, and consume under that scope. Supported framework consumers drain the operation; no manual current()/next() scope engine is needed.
- On completion, error or abandonment, destroy the owned inner generator while its request is still installed, then restore outer state in a nested finally even if handler cleanup throws. Avoid extra closure captures that keep the inner generator alive beyond cleanup.
- ReadResource::handle() resolves the resource Request through the container, sets its URI and template arguments, and scopes handler invocation plus eager/lazy serialization together. - AI McpServerTool keeps its own optional-package set/restore boundary and fully consumes lazy output before restoration. Exercise it with the real MCP provider, including lazy, overlapping and failed calls; retain the server's existing custom-request coverage. ## Argument shape and protocol validation

### Numeric property names, including execute_tools

The JSON schema serializer supports object properties named "0", "1", etc. Associative json_decode turns an object with only consecutive numeric names into a PHP list; upstream rejects it directly and again inside execute_tools. Preserve knowledge of wire shape without changing the public array representation or walking every decoded tree.

- JsonRpcRequest gains an internal nullable source-string property; Server assigns the already available raw message after from(). No constructor/from() signature changes.
- Request gains source()/setSource() accessors marked @internal and the additive public query isObject(?string $key = null): bool. Mark JsonRpcRequest's source property @internal too. setSource() invalidates its memoized object-mode decode.
- The query reads the current argument value: stdClass, associative arrays and empty arrays retain existing object-compatible behavior. Scalars return false. Only a nonempty list-shaped array with source data requires an object-mode decode.
- Memoize that decode per Request instance. Follow the queried dot path under params.arguments and check for stdClass. No second parse on ordinary arguments, shared decoder registry, shape tree, or arbitrary cache limit. Retaining the immutable source string uses PHP's reference-counted storage.
- The provider copies the source to custom Request subclasses and resource requests. Repeated independently resolved requests may each perform their own rare decode; do not introduce a shared holder merely to avoid that.
- toRequest() accepts original stdClass arguments and casts them to arrays without reapplying the list rejection. Otherwise construct the array-valued Request, attach the source, and validate it through isObject(). Type-check before construction so malformed scalar values become protocol errors.
- ExecuteTools keeps its existing array/range/name validation and defaults omitted arguments to an empty array. Use the shape query only for its ambiguous nonempty list-shaped arguments.
- ToolSearch casts the already accepted nested map to object when constructing its synthetic JsonRpcRequest. This prevents the second rejection while keeping the handler's Request values as arrays.

The owning-tool check has this shape; it does not make the transport know the calls structure:

    $arguments = $call['arguments'] ?? [];

    if ($arguments !== [] && array_is_list($arguments)
        && ! $request->isObject("calls.{$index}.arguments")) {
        throw ValidationException::withMessages([
            "calls.{$index}.arguments" => 'The arguments field must be an object.',
        ]);
    }

Direct PHP calls without wire source retain PHP-array semantics. This does not restore nested JSON types when later re-encoding application arrays; the existing AI nested-object limitation is unchanged. Do not document numeric-only wire arguments as a retained defect.

### Errors and inputs

- Reject valid JSON scalars and root arrays as Invalid Request (-32600), rather than allowing typed factory calls to throw TypeError. Distinguish malformed JSON (-32700).
- Validate reachable wrong parameter types at the owning method/shared boundary: cursor, page size, resource URI, prompt/tool name and completion ref/argument/context. Return Invalid Params (-32602), not reported internal errors. Preserve valid zero values.
- Require requested page sizes to be positive at pagination setup; zero must not produce the same cursor indefinitely.
- Validate LastModified at its constructor using an anchored date-time pattern plus checkdate(), accepting years 0001–9999 and YYYY-MM-DDTHH:MM:SS with optional fractional seconds and a required Z or ±HH:MM offset. Preserve accepted strings. Document the format in the annotations table and link concise README/porting-guide differences to it; add a short code comment explaining the client compatibility requirement. Extend the existing annotation tests with malformed dates, missing timezone, relative text, trailing newline and a valid fractional-offset case. Reject NAN in Priority with the existing range expressed positively; add one case to its existing tests. Leave raw annotation arrays unchanged.
- Preserve valid id-less error responses; they are permitted by the protocol.
- JsonRpcResponse::toJson() uses JSON_INVALID_UTF8_SUBSTITUTE and JSON_THROW_ON_ERROR for app response text. JsonRpcRequest and JsonRpcNotification use JSON_THROW_ON_ERROR without modifying argument/identifier bytes.
- Sync and lazy server error boundaries translate encoding failures, including non-finite numbers/depth failures, into protocol errors. If terminal error encoding itself fails, send an internal error containing only the decoded request ID and a fixed message, so the client can match its pending request. Do not add retries or catch-and-ignore fallbacks throughout the code.
- Stop PaginatesList before issuing another request when its requested item limit has been met.
- Replace truthiness filtering in the affected TestResponse assertion paths so legitimate "0" content is retained. Preserve "0" in Implementation titles/descriptions as well; only empty strings become absent metadata. Parse remote icons with the Icon constructor so their sources are preserved; local attribute icons still use Icon::from() for application URL resolution.
- TestResponse consumes iterable replies directly, retaining notifications before a late JsonRpcException and converting that exception into its terminal response. Keep PendingTestResponse's eager catch for list helpers; do not catch other exceptions. Recognize id-less error responses as responses, not notifications. Extend the existing prompt/resource notification fixtures with their past-date error cases, preserving both emitted notifications, and cover one id-less error directly.
- Use shipped configuration as the authority for tool-search limits; remove the conflicting max-tool-calls fallback. Apply typed getters and preserve documented optional/null settings.

## Server HTTP streaming

Keep the existing Server\Contracts\Transport contract and stream(Closure) callback behavior. Add an optional capability:

    interface StreamsMessages
    {
        public function streamMessages(Closure $producer, bool $cancelOnDisconnect): void;
    }

HttpTransport implements it. Server's producer invokes the existing protected send() for every JsonRpcResponse and yields control after that send. HttpTransport::send() invokes the existing sendStreamMessage() hook inside a one-message output buffer and retains the resulting SSE chunk; the transport yields buffered chunks after producer advancement. The capture handler collects even flushed output and returns an empty string, and its buffer closes in finally. This preserves hook overrides, exception timing, result metadata and cache hints instead of duplicating serialization.

- Ordinary/custom transports continue through stream(void callback) and send().
- Server determines modern/legacy mode from its validated request. Modern uses IterableStreamedResponse with cancellation enabled. Legacy drains through a callback StreamedResponse so disconnect does not cancel the producer. Merely setting cancelOnDisconnect(false) on an iterable response is insufficient: streamTo() still stops on a failed write.
- Keep existing direct HttpTransport::stream() echo and iterable callback forms supported. Following ResponseFactory::stream(), recognize generator closures with ReflectionFunction::isGenerator() and yield captured sendStreamMessage() output through IterableStreamedResponse, stopping after a failed write without opting into cancellation during waits. Other closures retain callback delivery. Remove connection_aborted(), which cannot observe Swoole client disconnects; add a short porting-guide pointer to the existing response cancellation documentation.
- Drain buffered output before advancing again, and after normal completion or a caught recoverable error. Never yield from finally on forced generator closure. Cancellation/failed writes abandon pending output and perform cleanup only.
- Handle late JsonRpcException and other ordinary failures at the shared producer boundary; prompt/resource generators must not leave clients with an unexplained truncated stream.
- Release the receive handler after initial HTTP dispatch. Transfer streaming ownership without retaining a Server -> transport -> stored callback -> Server cycle. Release stored producer/buffer references on completion, errors and abandonment, including a response never iterated. Stdio retains its handler for its server lifetime.
- Reuse the framework's existing disconnect handling. Do not add polling, a producer coroutine/channel adapter, or dependency workarounds. Preserve documented HTTP/2 limitations until the underlying runtime supports them.

## Client ownership, concurrency and cleanup

### Named clients

ClientManager retains factories at worker lifetime. Store built clients in ClientManagerState, implementing NonCopyableContext. Preserve the protected array $clients through a virtual by-reference get hook and set hook forwarding to that state's clients array; add a short WHY comment explaining ownership and protected-property compatibility.

Within coroutines, key state by CLIENTS_CONTEXT_KEY_PREFIX (`__mcp.clients.`) plus spl_object_id($this). Register one Coroutine::defer on first use, capturing the manager so its object ID cannot be reused while the context entry remains. Outside coroutines, retain a private nullable state on the manager; do not allocate global context entries or register defer. Separate the non-creating nullable lookup from the creating getter: disconnectAll() must not allocate state or register cleanup merely because a request terminates.

Keep the existing terminating hook. disconnectAll() detaches the current owner's clients before closing them, visits every client through the existing disconnect() hook even when one fails, and propagates the first uncaught failure after cleanup, replacing an ordinary failure only with a later CanceledException. Preserve that hook's upstream ClientException suppression. Repeated cleanup is idempotent and removes owned references even on failure. Mark registerClient() Boot-only: factories persist across requests; re-registration disconnects only the current owner's cached client, and other owners retain theirs until cleanup. Keep upstream's disconnect-before-install order.

This prevents one request's token/configuration from becoming another request's client and prevents termination of one request from disconnecting others. It also covers cancelled HTTP requests, for which the HTTP server skips kernel termination. No worker-wide sessions, OAuth tokens or client pools.

### Exchange capability and guard

One additive client capability declares exchange isolation and cleanup together:

    interface IsolatesExchanges
    {
        /** End the calling coroutine's exchange and release its response. */
        public function endExchange(): void;
    }

HTTP implements it; stdio and existing custom transports remain serialized. Protocol invokes endExchange() in finally around each attempt, including handshake attempts. It closes the matched reply without needing to parse outbound IDs in the transport.

Use one lazy per-Protocol channel guard inside coroutines; no lock outside a coroutine. Acquisition uses an occupied slot, not a zero-timeout probe:

    if ($guard->isFull()) {
        ConnectionResolver::releaseIdleConnections();
    }

    // A false result or cancellation is failed acquisition.
    $acquired = $guard->push(true);

Release by popping only after successful acquisition, in finally. A timeout of zero waits indefinitely in Hypervel's Channel; do not use it as a nonblocking try. Use internal unlocked helpers where guarded operations call one another; no second lock or general reentrancy mechanism.

| Operation | Non-isolating transport | Isolating HTTP transport |
| --- | --- | --- |
| connect/handshake | Guarded | Guarded; recheck connection after acquiring |
| request round trip | Guard covers connection, attempt and existing expiry retry | Capture negotiated connection under guard, then exchange runs independently |
| notify/version change | Guarded, with unlocked handshake path | Guard shared negotiation/session mutations |
| explicit disconnect | Guarded owner-wide cleanup | Coordinate with handshake; terminate the session and invalidate all exchanges, with bodies closed by their consumers |
| ordinary failed attempt | Existing owned disconnect semantics | Close only that exchange; conditionally invalidate negotiation |

Keep public/protected signatures unchanged. Protocol's request-ID increment does not yield. The transport configuration/header snapshot for each send must be captured before I/O. connect() loops while disconnected around the guarded connect helper, rechecking after guard release because waking a waiter can invalidate the negotiation before the caller resumes. Already-connected calls need no guard. Handshake failures still escape immediately; this is not another request retry. Cover a waiting protocol-pin change that runs during guard release, after which the original call must complete with the newly pinned negotiation.

For isolated failures, compare the captured NegotiatedConnection object with the current connection before setting connected=false. Retain the remembered connection version for upstream fallback negotiation. An old failure must not invalidate a newer negotiation. Do not send session DELETE or close sibling exchanges on ordinary failure, including failed renegotiation.

On SessionExpiredException, reconnect under the guard only if the captured connection is still current; otherwise use the replacement negotiation. Retry the original request only once, preserving upstream's session-expiry retry. Do not add retries for other failures or completed side effects.

### HTTP exchange state

Maintain a map of active exchange records keyed by current coroutine ID, with one non-coroutine slot. Each record owns its response body, pending JSON/SSE data and closed state. It is active state, not a retained lookup cache.

- Register the record before POST can yield. On return, if disconnect already removed/closed it, close the late body and fail that operation rather than resurrecting it.
- Own responses before status handling can throw. Close them on 401/403, 404, malformed replies, cancellation and success. Explicit disconnect closes/removes the caller's exchange and marks sibling records closed, retaining them until their owners call endExchange(). Never close a body while another coroutine may be reading it. A blocked sibling resumes cleanup when its current body read or line finishes or times out; an unbounded read remains unbounded. receive() checks closed state before body I/O or buffered delivery. Keep readLine() independent of exchange state.
- send() cleans up only the calling coroutine's leftover exchange, captures headers/session/version/token inputs, sends, then attaches the response to that record.
- receive() reads the next complete message from that exchange. JSON responses and SSE both retain upstream validation/error behavior.
- Separate connection reset from exchange cleanup. connect() resets negotiated shared state without erasing already sent sibling responses.
- Increment a private connection-generation counter whenever shared negotiation state is reset, including a protocol-era change. Each exchange captures it before header/token resolution or POST can yield. Where upstream resets on transport failure, authentication failure, session expiry or a rejected status, reset shared state only when that exchange's generation remains current; always close only its own exchange. This avoids a second timeout from teardown DELETE after an outage without letting an old failure erase a replacement session, even when its session ID is reused. Extend the old-failure regression to check the next request's session header, and the connection-failure test to assert disconnect sends no DELETE.
- Capture whether a send belongs to the guarded legacy initialization phase before POST yields. Only that response may publish the legacy session. Do not recheck the shared initialized flag after I/O: an old ordinary response can arrive during a newer handshake. Later response headers cannot overwrite a newer session.
- Explicit disconnect performs the upstream session termination; finally closes the caller's exchange, invalidates siblings and resets session state even when DELETE is cancelled. Cancellation passes through rather than being swallowed by session termination. Cover a cancelled DELETE with the same exception propagated, the caller's body closed and session state cleared.
- endExchange() is idempotent, removes the record and closes its body. Ensure primary errors survive cleanup. Public notifications also end their exchange after delivery; they must not leave an accepted HTTP response open merely because they bypass attempt().

### Incremental SSE

Do not drain an SSE response to EOF in send(). A server can leave the connection open after its final reply; receive must return that reply promptly and Protocol must close the body.

Parse complete events: join multiple data lines, support LF/CRLF delimiters, ignore comment/event/id fields, and retain upstream handling of unsupported server-initiated requests. Bound retained data to the current event/exchange; do not keep a queue of the entire stream.

Keep the existing latency-safe read strategy across supported HTTP transports. Do not switch to Response::lines() large reads on the PHP-stream fallback. Add MCP to the existing Guzzle buffered-reader follow-up in docs/todo.md instead of creating another task or workaround.

## Stdio and cancellation

### Client subprocess

Replace receive's waitUntil callback ownership with Process::getIterator(). waitUntil() and send()->isRunning() can read pipes before MCP's temporary callback sees the bytes; the iterator reads Symfony's retained incremental output and clears consumed buffers.

1. Pop any complete line already in the MCP buffer.
2. Before waiting, release idle database sessions through ConnectionResolver.
3. Iterate output; append stdout to the line buffer and return the first complete frame, retaining only unfinished/additional frames. Consume stderr into a bounded diagnostic tail.
4. Preserve idle-timeout behavior and convert ProcessTimedOutException into the existing TimeoutException.
5. At EOF, return a complete buffered frame if available; otherwise report the existing incomplete-output error with bounded stderr.
6. Disconnect and clean up the process/input at the owning lifecycle boundary. Protocol already disconnects non-isolating transports on failed attempts; do not duplicate a catch around receive(). For its own timeout and failWith() errors, build the primary exception before disconnecting and preserve it unless cleanup is cancelled. Share this rule in a narrow private helper.

Stdio disconnect closes and detaches its input, detaches its Process and clears both buffers before calling Hypervel's InvokedProcess::stop(0.1). Declare hypervel/process and reuse its shutdown behavior rather than duplicating it. Keep transport->connect() before Protocol's handshake try: the shipped stdio transport owns its process before start and retains cleanup ownership if start is interrupted.

Do not add a custom sleep loop or permanent callback alongside the iterator. Symfony's duplicate history spills to temporary storage, so describe the improvement as bounded retained output, not an unlimited-RAM claim.

### Server stdin

Use blocking fgets(STDIN) in Hypervel's hooked command coroutine to preserve complete lines without the 10 ms polling. Preserve serial message handling and stdout framing. Swoole 6.3.0RC1 misses hooks for standard streams inherited as sockets; ordinary pipes yield correctly, but inherited sockets block coroutine progress and upstream's nonblocking loop splits partial messages. Retain affected regressions with owner-approved version skips and removal TODOs until Swoole fixes this. Do not omit tests or add a package-side I/O workaround.

### Cancellation boundaries

Pass CanceledException through at actual I/O/application-code boundaries: Server::handle(), handler/stream response conversion, CompletionComplete, OAuth registration writes, client handshake fallback/probe and session termination. Do not report cancellation as a tool error, retry after it or wrap it as an ordinary protocol error.

Release resources owned by the operation and preserve its primary exception, except that cleanup cancellation replaces an ordinary primary failure. With no primary, propagate cleanup failures. Centralize this precedence in a small private Protocol cleanup helper used by disconnect and exchange cleanup; keep each operation's cleanup boundary explicit. Cover a non-isolating transport whose disconnect is cancelled after an ordinary request failure. Apply the isolated-exchange rules during concurrent handshake failure. Pure parsing catches are unchanged. Do not catch cancellation indiscriminately throughout unrelated source.

InvokedProcess::stop() owns interrupted shutdown: put the existing conditional idle-DB release and actual stop in one try; on failure attempt native stop(0) once, apply cancellation precedence and propagate the selected exception. Include zero-timeout stops because Symfony still waits briefly before killing the child. Keep the existing two release-failure cases and add interrupted-stop coverage for zero and positive timeouts.

PendingProcess owns a real child until start returns or run completes. Keep run's fake resolution, idle-session release and real execution in its existing try so fake-thrown Symfony timeouts retain framework conversion. After the timeout catch, use one private stopAfterFailure helper to stop through InvokedProcess and apply cancellation precedence; stopping an unstarted process is a no-op. Cover fake timeout conversion, run cancellation and an ordinary start/input failure through existing seams.

GuardsProcessOutput uses InvokedProcess for emergency stop, retains its re-entry flag and applies cancellation precedence. Pool startup rollback and InvokedProcessPool wait cleanup apply the same precedence locally; the pool stop loop visits every child and gives cancellation precedence over ordinary running/stop failures. Extend existing regressions rather than adding a failure matrix. Use mocks for stop sequencing and exact exceptions; existing real-child output tests cover termination. Add one MCP stdio ownership regression for detached state and propagated cancellation without duplicating process shutdown tests.

## OAuth, Origin and Inspector

Use Hypervel's existing PublicDestinationPolicy for OAuth discovery, metadata, token and dynamic-registration requests. The upstream literal-IP filter misses DNS names resolving to private destinations. Allow loopback only when the original MCP resource is itself on localhost, and retain redirect prohibition. Do not implement a second DNS policy.

Preserve ordinary configured/environment proxy routing. Resolve and validate the destination before dispatch, releasing idle database sessions before DNS, then pin the approved addresses on the unnamed request. Do not use withDestinationPolicy() here: that stricter API rejects ordinary proxy settings. Proxies that resolve target hostnames must enforce destination restrictions themselves; document this boundary as for AI remote files.

Add ResolvedDestination::curlResolveOptions() for the existing real-host CURLOPT_RESOLVE representation, including IPv6 formatting and no pin for literal hosts. Inside that method, after the literal-host early return, call CurlCapabilities::ensurePinningSupported() before constructing hostname pins. Its successful check is cached; callers do not repeat it. Reuse the method in curlOptions()'s proxy branch, AI UntrustedUrl and MCP; retain curlOptions()'s synthetic-host isolation for strict direct routes. Keep InteractsWithOAuthEndpoints::oAuthRequest()'s protected signature; put per-URL preparation alongside it. These downloads and OAuth calls remain buffered on the standard handler. Unsupported cURL runtimes fail clearly instead of silently discarding protection or referencing undefined constants. Do not add transport selection, proxy parsing or a second HTTP stack to MCP.

Document the hostname-pinning requirement (usable cURL with SSL support and libcurl 7.75+) in the MCP OAuth section and the AI remote-attachments section, linking to the HTTP client's existing destination-policy limitations. Keep the distinction that explicitly trusted AI hosts bypass these checks.

Validate a supplied Origin at the MCP route middleware boundary against the trusted application origin plus a new documented mcp.allowed_origins list. Derive the default from configured app.url, not the incoming Host header; normalize scheme/host/effective port. No Origin remains valid for non-browser clients; malformed, null or unapproved origins receive 403. Configuration needs a Laravel-style section header. Do not substitute CORS headers for execution-time validation.

Apply throttle:passport to dynamic OAuth registration using Passport's existing named limiter and application override behavior, attaching the middleware only when Passport is installed. Without Passport, retain the controller's graceful JSON 500 response instead of failing first on an unregistered limiter. Do not introduce a new limiter service or a hard package dependency merely for optional OAuth support.

Accept an allowed redirect domain's root URL, with or without a query, by comparing Str::before($value, '?') . '/' against the same allowedDomains() result used for the existing prefix check. Preserve redirect bytes and lookalike-host protection. Reject any fragment, including an empty fragment, in isValidRedirectUri() before wildcard, localhost or custom-scheme allowances, as required by OAuth. Extend RegistrarTest's existing redirect coverage with roots, queries, lookalike hosts and fragment cases.
