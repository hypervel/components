## Compatibility decisions

Keep existing Laravel public/protected method names, parameter names, ordering, and extension dispatch, except approved framework type adaptations. No deprecated Head API or legacy-version shim has been identified for removal. Preserve eager `defaults()`, `errors()`, and `inertiaGlobals()`; add runtime resolvers instead of changing their semantics.

These correctness fixes deliberately change two narrow upstream extension contracts:

1. **SSR health capability:** change `UniqueHeadGateway::isHealthy()` when the wrapped gateway lacks `HasHealthCheck` from `false` to `LogicException('The configured SSR gateway does not support health checks.')`. Upstream explicitly tests `false`. The wrapper advertises the interface, so otherwise `inertia:check-ssr` falsely reports an unavailable server. Keep supported gateway health results unchanged. No capability registry, alternate decorator classes, or broad exception catch in the command.
2. **Open Graph protected state:** replace the single protected `$defaults` flag with independent media provenance flags. One flag cannot describe a page image together with inherited default video/audio. Public constructors and methods stay unchanged; subclasses directly accessing that protected property need adaptation. Preserve `overlayMedia()` and `hasMedia()` as useful extension methods rather than retaining dead compatibility state.

Observable correctness fixes also belong in the owner summary: canonical query/fragment preservation, Open Graph media precedence, literal `"0"` values, manifest replacement, title/meta ownership separation, and direct builders honoring registered schema factories. These are bug fixes, not README differences. Generated content hashes change to `xxh128`, but remain deterministic; Inertia treats their values as opaque identifiers.

Keep Hypervel's `Ssr\Response::$head` and `$body` readonly. Return a new response when stripping duplicate Head tags. This is an internal immutable rendering result, not a read-only application: forms, mutations, database writes, and normal Inertia requests remain available. No JavaScript package fork or wire-protocol change is needed.

The owner also approved accepting `Paginator|CursorPaginator` in `paginate()` and `fromPaginator()`, and replacing pagination links as one complete relation set. Both paginator contracts expose the same previous/next URL methods. Replacement removes stale relations when the current page has no previous or next page; custom manual definitions must supply their complete set rather than relying on per-relation inheritance. Explain replacement briefly in code and document these behaviors in the Head guide; correctness fixes and additive support do not belong in the README differences or porting guide.

### Exception response status

Keep Head's early `renderable()` callback for ordinary Blade error views, which render before the final response exists. Also capture the actual response status before application response customization: exception `render()` methods, `Responsable` exceptions and earlier render callbacks can bypass Head's early callback, while `HttpResponseException`, authentication and validation responses can have a different status from its inferred 500.

Add `Foundation\Exceptions\Handler::beforeResponding(callable $callback): static`, with boot-only registration and a worker-held list of closures. Invoke them with `(Response, Throwable, Request)` after request-local `afterResponse()` callbacks and immediately before the single `respondUsing()` callback. Ignore their return values; response replacement remains with the existing APIs. Use a plain loop, without middleware, events or exception-type guesses. Add the matching `Configuration\Exceptions` delegate and facade annotation; leave the ExceptionHandler contract and forwarding fake unchanged.

Inside Head's existing handler-resolution callback, register this hook using the already-resolved manager and set its coroutine-local status from the response. Type the callback argument as the ExceptionHandler contract and check each optional hook with `is_callable` before registering it, preserving forwarding fakes and custom handlers without those methods. This ensures Inertia's `handleExceptionsUsing()` and application `respondUsing()` callbacks render metadata for the actual response status with the framework handler. Handler remains independent of Head. Document the additive hook in the errors guide. Code that renders Head inside a custom exception renderer before returning its response still supplies the intended status explicitly.

The Head regression throws its exceptions from an aliased route middleware closure: route actions deliberately unwrap `HttpResponseException` without invoking Handler. Preserve that routing behavior. Fix `TestResponse::decodeResponseJson()` to read its optional stored exception with null coalescing, so invalid JSON in a plain Symfony response produces the intended assertion instead of an undefined-property error. Add one exact-message regression alongside its existing stored-exception identity test.

## State ownership and replication

| Object/state | Lifetime |
| --- | --- |
| HeadManager configuration/resolvers, TagRegistry, SchemaFactory, SchemaValidator, HeadRenderer | Worker-shared; no captured request or tenant. |
| CurrentHead data and status | Coroutine-scoped binding; implements `ReplicableContext`. |
| HeadData, HeadBuilder, TagBuilder hierarchy, SchemaObject hierarchy, ResolvedHead | Implement `Transient`; caller-owned mutable state must not be auto-singletoned. |
| TagRenderer | Immutable configuration; worker sharing is safe. |
| ErrorPages | Manager-owned boot configuration, constructed with its definition closure; no transient marker needed. |
| Middleware, gateway decorator, macro/integration registrars | Worker-safe; retain only services/configuration, never request results. |

A container-resolution probe confirmed the actual failure: resolving the unmarked builder/schema twice returns the first mutable instance. Test normal container resolution of a builder and schema, not every subclass separately. Use the existing `Hypervel\Contracts\Container\Transient` marker.

Keep HeadManager's `request(): ?Request` signature and return `$this->app->make('request')`. Hypervel's binding returns the coroutine-local request or creates a request from `app.url` outside HTTP, preserving Laravel-style console/queue canonical rendering. Its guaranteed Request result makes upstream's `bound()` and `instanceof` guards redundant. Do not retain requests in the worker-shared manager. Resolve `CurrentHead` when needed rather than injecting a scoped object into the manager. Inertia detection reads its existing context state directly, as specified below.

Replication is explicit, not part of every layer merge:

```php
// HeadData: clone builders only when an independent state copy is requested.
public function replicate(): static
{
    $replica = clone $this;
    foreach ($this->builders as $class => $builder) {
        $replica->builders[$class] = clone $builder;
    }
    return $replica;
}

// CurrentHead: copy data and retain the current status.
public function replicate(): static
{
    $replica = clone $this;
    $replica->data = $this->data->replicate();
    return $replica;
}
```

Do not add a deep `HeadData::__clone()`: `merge()` and `asDefaults()` already clone layers repeatedly. Add `Schemas::__clone()` to clone each stored SchemaObject and rebuild its identity key with the cloned object's `spl_object_hash()`. Keep content keys for array schemas. Stale object keys can collide with reused identities after original objects die.

Built-in schema setters normalize nested SchemaObject/DateTime values into arrays/scalars; do not add a generic recursive SchemaObject clone engine. Custom builders or schema subclasses holding additional mutable objects own their `__clone()` behavior. Raw foreign objects supplied as application data retain normal PHP object semantics.

`flush()` clears runtime tags and status for the current coroutine. Fresh requests are naturally isolated. For sequential independent pages or tenant switches within one coroutine, the application calls `flush()` between pages; do not silently flush during arbitrary tenancy transitions or invent Head-specific tenant partitions.

## Runtime extension points

Add these replaceable nullable closure slots to HeadManager, with facade `@method` entries:

```php
public function resolveDefaultsUsing(?Closure $resolver): static;
public function resolveErrorsUsing(?Closure $resolver): static;
public function resolveCanonicalOriginUsing(?Closure $resolver): static;
```

Callback contracts: defaults `(HeadBuilder $head): mixed`; errors `(HeadBuilder $head, int $status): mixed`; canonical origin `(): ?string`. Return values from builder callbacks are ignored, like existing `defaults()`. Registration returns the manager and null removes the resolver. No callback stack or per-tenant resolver registry.

Use fresh HeadData and the existing `define()` path on every resolution. Precedence:

1. Eager defaults.
2. Runtime defaults, marked `asDefaults()` to preserve fallback media and title suffix semantics.
3. Route groups and route layers, in their existing sequence.
4. Current runtime page data.
5. Static error defaults/status data.
6. Runtime error data, when the effective status is non-null.

The explicit render status takes precedence over CurrentHead status. Do not impose a new `>= 400` restriction; upstream supports explicit registered statuses. Run the error resolver even when no static error definition matches. Do not memoize resolved defaults/errors: repeated renders and same-coroutine context changes must observe current data.

Document boot-only registration for these hooks and existing shared mutators (`defaults`, `errors`, `inertiaGlobals`, `inertia`, `extend`, schema registration, and the matching registry/error-definition methods). Capture worker-safe services in provider boot, then read tenant/request data inside callbacks. Never capture the currently active tenant during boot or mutate global config per request.

Use generic teams and their settings in public examples. Do not reference private packages, application code, or product plans. Example, using an application-owned worker-safe context service whose `settings()` reads already-loaded team settings:

```php
public function boot(TeamContext $teams): void
{
    Head::resolveDefaultsUsing(function (HeadBuilder $head) use ($teams): void {
        $settings = $teams->settings();
        $head->title($settings->name, suffix: ' - '.$settings->name)
            ->description($settings->description)
            ->canonical()
            ->manifest($settings->manifestUrl);
    });

    Head::resolveErrorsUsing(function (HeadBuilder $head, int $status) use ($teams): void {
        $head->title($teams->errorTitle($status));
    });

    Head::resolveCanonicalOriginUsing(fn (): ?string => $teams->canonicalOrigin());
}
```

Callbacks can execute multiple times per response (Inertia sharing plus Blade rendering, or repeated explicit calls). Reuse loaded settings; Head adds no database/network round trips. Application logic can use all existing fluent metadata and schema APIs in these callbacks.

Keep `inertiaGlobals()` static, server-owned document tags. Tenant branding, icons, manifests, and any changeable metadata belong in page-managed defaults/runtime data. A runtime globals hook would still leave stale client tags after navigation and is not the correct solution.

## Canonical URLs

Add `Canonical::resolveOriginUsing(?Closure $resolver): void`, with static nullable callback and `flushState()`. HeadManager delegates its canonical registrar here, so direct Canonical rendering and manager rendering share one policy.

- Origin contract: `scheme://host[:port]`, without a path; null preserves normal request-derived behavior. Match UrlGenerator's no-argument callback style.
- Apply only to automatic and relative canonical URLs. Explicit absolute HTTP(S) URLs, recognized case-insensitively, and protocol-relative URLs keep their own host. For protocol-relative URLs, use HTTPS when forced, otherwise the request scheme when available; retain the protocol-relative form when rendered directly without a request and HTTPS is not forced. Existing normalization options still apply.
- Automatic canonical path preserves the request's base URL and path, omits query as upstream request `url()` does, and uses the runtime origin when available. Outside HTTP, HeadManager uses the `app.url` request; the resolver replaces only its origin. Console/queue callers supply the intended page path when rendering a specific page. Direct `Canonical::render(null)` preserves upstream behavior: automatic mode emits no canonical, even with an origin resolver, because no page path is known. Explicit relative paths can use the resolver origin.
- Preserve constructor, `render(?Request)`, and `normalizeUrl(string, ?Request, bool, bool)` signatures and override dispatch.
- Normalize only the URL path. Detach query/fragment without re-encoding them, normalize the path/root slash, then append the untouched suffix. `https://tenant.test/?page=2` must not become `https://tenant.test/?page=2/`. Preserve ports, encoded paths, and fragments. Do not build a general URL validator/parser abstraction.

## Rendering correctness and bounded optimization

| Change | Implementation and reason |
| --- | --- |
| Open Graph fallback media | Track default provenance independently for image/video/audio. Higher-layer media replaces only default media of its own kind. If the overlay has no media of that kind, inherit base provenance; otherwise use overlay provenance. Preserve provenance when two defaults layers merge. Keep the existing `overlayMedia` signature and replacement policy; use `hasMedia()` in `isEmpty()` so the protected hook remains meaningful. |
| Literal `"0"` metadata | Title/Description emission and OG/Twitter fallback checks must distinguish null/empty strings from `"0"`. Their `headArray()` filters must also preserve `"0"` instead of dropping it through truthiness. Keep existing empty-string omission where currently intentional. Test both rendered tags and arrays. |
| Manifest override | `GenericLinks::link()` keys `rel=manifest` as one logical link, so a tenant/page URL replaces the inherited manifest. Render its Inertia identity consistently as a singleton. Keep multiple icon candidates and other repeatable links; no broad icon key rewrite or removal/tombstone API. |
| Title ownership | In `uniqueInertiaElements()`, treat title as its own bucket and other tags by `data-inertia` key, matching Inertia core `collect()`. A title and `<meta name="title" data-inertia="title">` both survive. Keep existing semantic ownership keys. |
| Schema factory consistency | `HeadBuilder::schemaFactory()` uses `Container::getInstance()->make(SchemaFactory::class)` when no factory was supplied. Honor explicitly injected factories. Direct/DI-created builders then see registered custom types and reuse the worker factory. Container auto-creation permits standalone use. This is a bug fix; no user-doc escape-hatch section. |
| Schema values | Magic setters use the sole supplied value regardless of its argument name, preserving explicit null; only an omitted argument means true. Infer types from the unchanged concrete class short name, without inheriting parent attributes. Bulk FAQ/breadcrumb helpers cast numeric array keys back to strings. The existing validator descends into nested SchemaObject values through `toArray()`; raw schema arrays otherwise retain their serialization and reference semantics. |
| Pagination | Replace the complete relation set on overlay, including an empty set. Accept ordinary and cursor paginator contracts. Advertise no pagination route attribute because pagination is supplied through the runtime API. |
| Feed route values | Accept bare URLs and lists of URLs as untitled RSS feeds. Keep URL-to-title maps and structured definitions; omitted or null structured titles mean untitled, while other supplied titles must be strings. Omit empty title attributes when rendering. |
| Meta ownership | Preserve semantic keys and aliases for the normal inferred name/property attribute without media. Hash the full stored identity when the attribute is explicitly different or media is present, preventing distinct tags from colliding while retaining overrides of dedicated builders. |
| Registry/input consistency | Make repeated registration of the same custom builder a no-op before checking other builders' route keys. Resource-hint scalar list entries require integer keys; reject ambiguous URL-to-string maps through the existing invalid-value path. Preserve other builders' established filtering of unusable list entries. |
| Route attribute lookup | Memoize TagRegistry's route-attribute map on the instance, invalidate after successful `extend()`. Its key set is bounded by registered builder classes. No static cleanup for this instance-only cache. |
| Schema reflection | Cache inferred SchemaType/class-derived type by concrete class, preserving explicit constructor types and protected `typeFromAttribute()` dispatch. Bounded by loaded schema classes; add `flushState()`. Do not cache tenant values or SchemaObject instances. |
| Content hashes | Replace md5 in TagRenderer, MetaTags and array-schema keys with deterministic `xxh128`; preserve semantic keys. No random worker seed: keys must match across requests/workers and SSR/client handoff. These hashes are identifiers, not trust boundaries. |
| JSON-LD rendering | Encode once in `TagRenderer::jsonLd()` with existing safe JSON flags, derive any default key from that same encoded string, then emit it. `Schemas::toTags()` passes the schema without pre-encoding for a redundant explicit key. Keep explicit supplied keys, escaping, invalid-UTF-8 failures, and schema validation behavior. Insertion-time array content hashing remains separate. |

Do not cache combined route HeadData: sequential overlay order matters, especially for custom builders whose merge operations are not necessarily associative. Keep ResolvedHead local to each render; its simple lookups do not need another cache. No output cache, tenant-key cache, dynamic worker cache, database schema, or benchmark claims.
