# Framework Correctness Improvements

## Scope and status

Independently useful database, queue, validation, decimal-casting and JSON-decoding improvements. Keep this plan independent of private applications and packages; describe framework requirements without their names, paths, or domain details. Preserve Laravel signatures and protected extension points, except for explicitly approved behavior changes.

The 0.4 integration preserves both sets of supported behavior. Record further framework changes here when they warrant planning, without duplicating consumer-specific implementation plans.

## Design

- **Database capability:** add `Connection::supportsSkipLocked(): bool`, false by default, rather than widening the driver-neutral `ConnectionInterface`. PDO implementations reuse the current engine/version decision and its connection-local memoization/reset behavior. Preserve configured version overrides and MariaDB detection through either driver: supported MariaDB servers at the 10.11 baseline, MySQL 8.0.1+, Vitess/PlanetScale 19+, PostgreSQL 9.5+; SQLite remains false. Migrate Database Queue's internal capability use while preserving `getLockForPopping(): bool|string` and its invocation. Outbox claims use the same capability and the fluent locking API, retaining their PostgreSQL CTE and conditional-update fallback. Do not retain parallel engine/version logic; retire superseded `@internal` popping helpers after their callers migrate.
- **Query-builder API:** add fluent `lockForUpdate()->skipLocked()` without changing `lockForUpdate()` or `sharedLock()` signatures. The no-argument modifier requires an existing update/shared lock; reject custom-string combinations in either setter order. Carry intent structurally; grammars own engine SQL, including MySQL's `for share` versus MariaDB's `lock in share mode`. Unsupported versions retain their normal lock behavior; callers needing a nonblocking claim check the connection capability and choose compare-and-swap updates. No lock-mode class hierarchy or domain-specific framework claim service.
- **Queue middleware:** add `RateLimited::releasePadding(int $seconds): static`, nonnegative, with a default of three seconds preserving current behavior. `releaseAfter()` retains fixed-delay precedence. Include the property in the serialization whitelist. Callers can opt into `releasePadding(0)` without additional I/O or lookup for existing jobs.
- **Validation defect:** guard both numeric field operands of `gt/gte/lt/lte` with their respective attribute names. Guard `multiple_of` input through `validateMultipleOf()` in compiled and delegated execution, preserving the calculation hook's signature. Exponent rejection and numeric parse errors fail validation rather than escaping as math exceptions. Comparison-message formatting preserves the `getSize()` hook and displays the original trimmed value if its exponent is rejected, without expanding it or throwing again. Preserve the attribute-aware override callback; developer-supplied rule literals remain trusted. Components already require Brick Math 1.0; no further version migration is needed.
- **Decimal casts:** prevent scientific-notation expansion beyond ±1000 in request and Eloquent decimal casts, throwing their existing math exception. Share exponent extraction through internal `Number::exponent()` and the default `Number::MAX_EXPONENT` with validation, without limiting ordinary decimal-string length or changing rational parsing. Include `int` in Eloquent's decimal-cast input type so integer values retain their precision instead of passing through float conversion. Test both casts, exponent boundaries, unchanged explicit decimals/fractions and large integer precision with bounded inputs.

### Write index hints and outbox lock scope

- Retain index hints on MySQL/MariaDB updates and forced indexes on plain SQLite updates. Honor MySQL/MariaDB DELETE hints through the native single-target multi-table form when an unjoined delete has no ordering or limit; honor hints on joined deletes as well. Derive the delete target before appending the table hint, preserving aliases and prefixes. Keep unhinted SQL and ordered/limited unjoined deletes unchanged. Plain SQLite deletes use `indexed by`; joined, limited and offset SQLite writes keep their existing selection subqueries. PostgreSQL remains unchanged.
- Explain this intentional difference from Laravel beside the grammar: ignoring requested indexes lets InnoDB scan and lock unrelated rows. A missing named index raises the native error. Hints do not guarantee lock confinement: an ID-only delete or locking read can still choose a covering scan. Retain real ownership/eligibility predicates; do not insert dummy predicates or introduce an exact-ID delete API. A caller requiring confined ID-only deletion needs its own driving-ID join. Document supported forms and limitations in query feature documentation; no README differences or porting-guide entry.
- Apply a shared native primary-index gate to outbox exact-ID mutations and claimed-row lookups while preserving lease and eligibility predicates. InnoDB claims select only IDs and original eligibility through the ordered due index, update those IDs, then read the owned message bodies within the transaction. This adds one bounded read and prevents payload selection from choosing a scan/filesort that locks beyond the batch. Allow three framework transaction attempts: concurrent due-index scans can share an end gap and deadlock when claim updates move their entries to future lease deadlines. The database-only closure can safely retry with its original token after rollback. Share the owned-row lookup with conditional claims; PostgreSQL retains its single-statement claim. Legitimate short SKIP LOCKED batches remain valid, but parallel relays must make progress when due rows outside each other's bounded batch are available. Cover native and conditional claim updates, accepted/deferred/failed settlement and operator batch retries. Express failed-release CASE updates through the builder using internally generated integer deadlines; keep external values bound and account for the three remaining non-ID bindings.
- Extend existing grammar and native index-hint tests for deletes, aliases, prefixes, joins, limits and missing indexes. Extend the existing native outbox fixture for mutation contention rather than adding another harness. Verify MySQL 5.7/8.4/9, MariaDB 10.11/12.3, PostgreSQL and SQLite behavior as applicable, including the conditional claim path on MySQL 5.7. Complete formatting, analysis, affected tests and peer review before committing.

### Model-specific Eloquent builder types

- Let `UseEloquentBuilder` accept `class-string<Builder<*>>`, matching the existing builder property and factory return type. The attribute accepts builders bound to a particular model; `Builder<Model>` incorrectly excludes them because the model parameter is invariant. Align the resolved-class cache and resolver return annotation with the same boundary. Runtime construction and public signatures remain unchanged.
- Cover the attribute with a model-bounded generic builder and `HasBuilder`, including a model subclass and a terminal query result in the type fixtures.

### Constrained relationship-loading types

- Correct model loading annotations to accept keyed constraints and nested relation specifications already supported at runtime, including model and collection `fresh()` and both paginator morph-loader families. Eager callbacks receive `Relation`; aggregate callbacks receive the related Eloquent `Builder`. Align the forwarding methods without changing native signatures or execution.
- Morph loaders take a map keyed by class names or morph aliases, including integer aliases, whose values are relation specifications or strings. Keep the actual outer map shape in the existing fixtures and cover string/integer aliases across model, collection and paginator loaders. Aggregate constraints accept names, builder callbacks and empty arrays, not nonempty nested relationship arrays; preserve the corresponding callback-inference assertions without claiming nested aggregate support.
- Extend existing model and collection type fixtures to verify constrained inputs, callback types and fluent returns. Keep the separate `Builder::with()` callback parameter's native `Closure` type; its array form supports callable constraints. Reuse existing aggregate callback runtime tests rather than adding duplicate cases. Run source and fixture analysis and affected database tests.

### Raw attribute replacement

- Clear both Eloquent cast-value caches and their stored-value tracking before `setRawAttributes()` optionally calls `syncOriginal()`. Synchronization reads attributes through the cached casts; clearing afterwards lets stale objects overwrite the replacement values and marks those wrong values clean. Preserve the signature and unsynchronized replacement behavior, and explain the intentional ordering difference beside the code. Retain the incoming cached-object reconciliation and its distinct in-place-mutation regression alongside the accessor-cache and unsynchronized-replacement cases.
- Use one regression parameterized over synchronization, covering both `AsArrayObject` and an `Attribute` getter/setter object. Check replacement values, raw originals and dirty state without database setup.

### Immutable date modifier types

- Keep `CarbonImmutable::addMonths()` metadata typed as `static`, including its optional anchor-day argument. Carbon preserves subclasses at runtime; inherited metadata naming the base class incorrectly widens fluent results. Extend the existing modifier type fixture and reuse the runtime metadata/subclass test. No runtime or API behavior changes.
- The complete fix belongs in Carbon's PHPDoc generator, which emits concrete class names for fluent returns. Retain the existing local annotations until a corrected release is adopted, then remove the redundant annotations and their reflection test while keeping type regressions. Track that dependency update and cleanup in [the framework todo](../todo.md#framework-wide); do not duplicate Carbon's full generated method list here.

### Exact JSON numbers

- Add `Json::decodeNumbersAsStrings(string $json, bool $assoc = true, int $depth = self::MAXIMUM_NESTING_DEPTH): mixed` for exact numeric API inputs. Return every numeric token as its original string, including integers, trailing zeros and exponent notation; preserve ordinary strings, booleans, null and native array/object shapes.
- Validate the original document through `Json::validate()` before quoting numeric tokens: quoting alone can turn malformed input into valid JSON. Use a linear walk that skips existing strings and escaped bytes, then delegate to `Json::decode()`. Retain native errors and the existing public depth convention. No new parser framework, number wrapper, flags parameter or changes to ordinary decoding.
- Cover exact values, escaped strings, associative/object results, malformed numbers and object keys, invalid UTF-8 and depth limits in the existing JSON tests.

### Pooled in-memory database restoration

- `RefreshDatabase` and `DatabaseTruncation` must restore cached SQLite databases at the physical pool owner. Setting the PDO only on a logical lease loses the restored schema when setup releases that lease; `LazilyRefreshDatabase` shares the affected refresh path.
- Add `DatabasePool::restoreSharedInMemorySqlitePdo(PDO $pdo): void`, marked `Tests only.` Drain idle wrappers through existing pool cleanup, then replace the shared PDO. Subsequent borrows use the current factory and dispatcher. Preserve normal connection/lease semantics and add no production hot-path work.
- Add testing `DatabaseConnectionResolver::restoreInMemoryPdoIfPooled(UnitEnum|string|null $name, PDO $pdo): bool`, also marked `Tests only.` Reuse `poolEnabled()`; return false without resolving connections when disabled. Return true immediately when the named pool already holds the supplied PDO, before releasing any leases. Otherwise release idle leases, restore through that pool and return true. Preserve existing physical-pool name resolution.
- In `LazilyRefreshDatabase`, restore cached in-memory databases before resolving connections and registering lazy callbacks, using the existing `usingInMemoryDatabases()` condition. Migrations and transactions remain lazy. The callback's ordinary restoration becomes a no-op for an already-restored pool, so query-first, cursor-first and explicitly pinned first use retain normal session behavior. Explain this upstream difference concisely; do not change production query or foreign-key suppression pinning.
- Keep both traits' Laravel protected signatures and bare restoration bodies unchanged. Use the pooled operation only when a bound `db.resolver` is the testing resolver and the operation returns true. Custom resolvers and manager doubles retain the existing PDO/type-check/dispatcher path. Do not implicitly read test state during pool construction, add a registry, remigrate every test or substitute a file database for this fix.
- Document that in-memory SQLite pools use one session and serialize queries; tests requiring simultaneous database sessions still need a file-backed or server database.

### Cancellation through database callbacks

- Recognize cancellation carried by a callback or cleanup exception through `Coroutine::causedByCancellation()`, preserving the original exception and foreign-cancellation ownership. Query execution and streaming must not wrap cancellation, retry it, count it as a query error or dispatch `QueryFailed`.
- Stop commit callbacks on cancellation. Finish rollback callbacks while retaining cancellation ahead of ordinary failures. Apply the same rule through transaction manager/event notification and recovery boundaries, connection disconnect and retained-connection termination. Keep native-only PDO and join checks unchanged; do not add speculative cleanup machinery.
- Never retry a canceled transaction or wrap its failure as a deadlock, even when its cleanup exception names a deadlock.
- Extend existing cancellation tests with chained exceptions at query, transaction callback and cleanup boundaries. Preserve public signatures and ordinary-error behavior. Validate the framework and affected database consumers together.
